# 后端

`Backend` 包含六个标量发射队列、两条整数/分支流水线、一条共享乘除浮点流水线、两条访存
流水线、原子执行单元、整数与浮点物理寄存器堆、旁路网络、唤醒网络和 DCache。ROB、SQ 与
Store Buffer 由 `Commit` 持有，通过专用接口连接。

性能配置复用这些标量执行资源，并增加独立的向量计算队列、访存队列和 SIMD8 执行通路。
原子单元和 DTLB 在该配置下不例化，AGU 结果作为物理地址访问 DCache。

## 发射队列

两条整数/分支队列各 6 项，`MixArith` 队列 6 项，LS0 Load 队列 5 项，LS1 地址队列 6 项，
Store Data 队列 5 项。队列以固定物理槽保存 payload，用年龄关系选择最老的可执行任务；
每拍可接收最多三条派发任务。两条整数队列各有 3 项独立 replay 存储，用于保留带推测依赖的
已发射任务。Replay 的寄存容量许可包含在途快照的预约，发射选择直接读取该许可，
快照写入、推测确认与失败恢复共同维护下一拍容量。Load 发射后
保留原队列表项，直到完成或 replay；replay 直接重新激活原表项。

向量计算队列为 6 项，访存队列为 4 项，二者复用 `IssueQueue` 的固定槽与年龄选择。
队列保存配置、物理标签和控制信息，向量数据保存在 PRF。LMUL 分组由执行单元展开，
一条架构指令仍占用一个 ROB 表项。

性能配置的推测状态汇总与操作数掩码并行更新：每个唤醒源先计算剩余推测标志，
再按标签匹配选择一位结果，避免在宽掩码选择后继续归约。

## 执行流水线

`Arith0` 和 `Arith1` 均使用 `ArithBranch`，执行整数 ALU、条件分支、JAL 和 JALR。两条流水线
具有相同的 RF、EX、WB 边界，并可互相接收旁路结果。

`MixArithPipeline` 执行整数乘除、FP32 加减乘、融合乘加、除法、平方根、比较、分类、符号操作、
搬运与整数/浮点转换。CSR 指令也由该队列发射，并在获得 `Commit` 的按序授权后访问 CSR 状态。
中端译码为该通路提供零立即数或 17 bit CSR 操作数字段；取指与译码异常随指令包直接传递。

LS0 只执行 Load。LS1 执行 Load 和 Store Address，并从独立 Store Data 队列读取写数据。两条
Load 通路在发射后先写入流水寄存器，下一拍读取 PRF 并由 AGU 生成虚拟地址。AGU 结果只写入
DCache 请求寄存器和同步 RAM 读地址；随后 DTLB 地址翻译与 Tag/Data RAM 返回并行完成。两条
Load 通路都查询 SQ 与 Store Buffer，按字节合并比 Cache 更新的 Store 数据。

LS1 的 Store Address 使用相同的发射、PRF 和 AGU 边界，并在 AGU 后增加独立的 D1 寄存器。
DTLB 查询、PMA 属性、对齐检查和 SQ 地址写入均使用该寄存器中的地址与任务信息。D1 支持在
当前地址写入 SQ 的同时接收下一条 Store Address；DTLB miss 或 SQ 反压会保留当前内容。

`AtomicUnit` 执行 `LR.W`、`SC.W` 和九条 `AMO.W`。地址与写数据仍经 LS1 的地址和数据任务写入
SQ；指令到达 ROB 头且更早的存储访问排空后，原子单元复用 DCache 的 LS1 Load 端口与 Store
端口完成操作。Reservation 以物理字地址记录；已提交 Store 仅在写入该字时使其失效，
成功或失败的 `SC.W` 以及其他 AMO 也会清除它。

DCache 根据 PMA 属性区分可缓存、可合并和强顺序 Store。可合并 Store 在提交后进入专用队列，
普通设备 Store 与原子操作仍沿原有单次事务路径执行。合并条件、AXI burst 和顺序保证见
[存储系统](Memory.md#pma-与非缓存写合并)。

## PRF、旁路与唤醒

整数 PRF 为 64 x 32 bit、9 读 5 写；浮点 PRF 为 40 x 32 bit、4 读 3 写。读端口在执行单元
停顿时保持地址。写端口按物理地址更新不同表项，MixArith 写口可使用独热直写选择；同拍写回
经读旁路返回最新值。旁路网络包含两条 Arith、MixArith 和两条 Load 共五个生产者。

唤醒网络区分计算唤醒与访存唤醒。Arith 根据消费者类型在发射或 RF 阶段提供唤醒；MixArith
在 EX2、EX3 和 WB 边界提供唤醒；Load 在 D1 发布带推测标签的唤醒，并在 WB 发布确定性唤醒。
`LoadSpeculationTracker` 在命中、异常或 replay 后确认或撤销对应标签。

MixArith 的写回结果在 WB 边界寄存后同时供旁路网络与物理寄存器堆使用；写回目标和有效位仍由对应指令的标签与提交恢复状态决定。
MixArith 的 WB 唤醒目标与有效位也在同一边界寄存，计算域和访存域在原有 WB 周期使用其 Q 端。

性能配置为向量操作数收集增加一个整数读口和一个浮点读口，标量 PRF 分别为 10 读 5 写、
5 读 3 写。向量 PRF 独立保存 64 个 256 bit 物理寄存器，由八份原 `Regfile` 组成，每份
为 64×32 bit、三读两写。计算、多拍运算和访存收集共用三组读口；计算与 Load 分别拥有
一个写回口，按字节写入以保留未更新的元素。

仿真接口按物理寄存器分别导出观测值，退休差分直接读取对应寄存器。
观测接口只在仿真配置中例化，综合配置不包含这部分连接。

向量指令产生的标量结果复用 LS1 写回端口，写入后由寄存标签发布确定性唤醒。
LS1 占用唤醒位置时保留该标签，并对新的向量标量完成施加反压。

向量读口先仲裁物理标签，RF 将六位地址拆成八行与八 bank 的并行选择，组合读延迟保持一拍。
计算通路在上一组收集结束的边界
捕获下一组标签，连续任务每拍可收集八个 INT32 或 FP32 元素。向量 ReadyBoard 在 RF
写入后发布就绪，因此向量 RF 使用存储值直接读取。

`VectorArithmetic` 例化八路共享 ALU、乘法与 FP32/FMA 单元。多拍通路按元素复用共享
除法、平方根、转换和浮点逻辑模块，处理归约、排列与复杂宽度操作。
运算标志随架构指令汇总，在退休时更新浮点和向量 CSR。

## 取消与完成

提交恢复清空所有发射队列和执行流水有效位。执行结果通过专用完成端口送入 ROB；分支流水线
同时返回实际方向、目标和误预测状态。Load 完成还携带虚拟地址与访存异常，Store 地址和数据
分别写入 SQ。原子结果复用 LS1 的 ROB 完成端口和整数 PRF 写口。
